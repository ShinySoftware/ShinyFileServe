Features

Everything a team file server should do. Nothing it shouldn't.

Built for a studio, an office or a house full of people: real permissions, real limits, and a record of everything that happened.

Groups and permissions

Grant List, Download, Upload, Delete and New Folder per group, per share. Someone in two groups gets the union — adding a person never takes access away.

Quotas that hold

Cap downloads and uploads by day, ISO week, month or in total — per folder grant and per account across the whole server. Limit how many transfers someone runs at once.

Share links and galleries

Hand out a file or folder as an address — for anyone, or for particular accounts — with optional expiry. Folders open as a photo and video gallery with a full-screen viewer.

A complete audit log

Every sign-in, transfer, deletion and refusal is recorded and filterable by person, action and date. Refusals are logged, not just successes.

Live transfers and bandwidth

See who's signed in and what's moving right now — speed, progress and time left. Report bandwidth by day or hour, by account, over any window.

Virus scanning before publish

Uploads are scanned once whole and only moved into place if clean — by Windows Defender through AMSI, or a ClamAV daemon on macOS and Linux.

A public address, on demand

Open a tunnel from the tray to get a public HTTPS address for people outside your network. Close it and the server is back to LAN-only.

Backup and restore

Download the whole configuration — accounts, shares, quotas, history and log — as one consistent file while serving. Restore checks the backup before touching anything.

Lives in the tray

Start and stop the server, open the tunnel and copy the address from the menu bar. The icon turns green while somebody is connected. Starts at login if you want it to.

The desktop app has no screens of its own — it's a window onto its own server. Whatever an operator does from the machine, they can do from anywhere on the network.

Sharing

Send a link, not an attachment.

Click 🔗 beside any file, or Share on a folder. Pick who it's for — anyone with the link, or particular accounts — and when it should stop working.

  • Links borrow, they don't grant. A link lends its creator's rights, re-checked on every click. Remove the creator's access and every link they made closes.
  • Quotas still apply. Downloads through a link count against the creator, so an "anyone" link is never a way around a limit.
  • The right address, automatically. Links use the public tunnel when it's open, otherwise the LAN address — never 127.0.0.1.

Package feeds

A private NuGet feed and npm registry, too.

Switch them on in Settings and the same server hosts /nuget and /npm. Personal access tokens authenticate them; the same groups govern them.

  • Restore, push and unlist for NuGet; install and publish for npm — granted per group, overridable per account.
  • Tokens are shown once and stored only as a SHA-256 hash. Lock an account and its tokens stop on the next request.
  • Anonymous access can be reads at most — never a write nobody can be held to account for.
  • Every feed request is logged: who, which token, which package, status, bytes and duration.

Security

Careful by default.

Nothing is seeded on first run. The administrator is created by whoever opens the app — and only from the machine running it.

No default password

An account the whole internet knows the password to is worse than none, so there isn't one. The first admin is created locally.

Invisible by default

A share you have no grant on answers 404, not 403. You don't learn it exists.

Strong hashing

Passwords are PBKDF2-SHA256 at 210,000 iterations. Access tokens are 256 random bits, stored only as a hash.

Path traversal refused

Every file operation goes through one check that rejects .. and verifies the canonical path against the share root, symlinks included.

DNS rebinding blocked

Requests must name the server by IP, its own host name or the open tunnel. Anything else gets a 421.

Lockout without leaks

Accounts lock after repeated failures, and a wrong password on a locked account reads exactly like any other wrong password.

Password policy

Length, character classes, common-password checks and maximum age — validated by the server on every path, not just in the browser.

Tunnel-aware trust

Loopback sign-in only applies to connections that didn't arrive through the tunnel. No header can claim it.

Technology

Built on .NET 10, top to bottom.

One C# codebase drives three native desktop heads, an embedded HTTP server and a WebAssembly portal. JSON is source-generated end to end — no reflection, trim-safe on every platform.
